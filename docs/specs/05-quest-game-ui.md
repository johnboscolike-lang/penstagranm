# 상세 명세서 05: 우리반퀘스트 게임 UI

pen스타그램의 네 컷 기록·댓글·전사·달력을 **아기자기한 도트 RPG 세계**로 묶은 화면 명세다.
기획 원문은 "우리반퀘스트 통합 기획"(학교 / 주간도전 / 내공간 3공간, 매주 새 출발, 누적 성장)을 따른다.

## 화면 구성 (3공간 + 하위 화면)

| 공간 | 경로 | 핵심 |
|---|---|---|
| 학교 | `/` | 오늘의 학교(다음 수업·급식·공지·일정). 점수·잠금 없이 바로 확인 |
| 학교 › 달력 | `/calendar` | 날짜 선택과 일정 등록을 한 페이지에서 처리 |
| 주간도전 | `/challenge` | 오늘 약속 3칸, 이번 주 팀·개인 순위, 참여 보상 진행 |
| 주간도전 › 기록 | `/record` | 준비·목표·필기·과제 **네 컷 4칸 모두 필수** + 한국어 전사 |
| 내공간 | `/myroom` | 내 정보, 지난주 성장 소식, 앞마당 꾸미기, 네 컷 성장 기록·댓글 |

- 모든 화면은 `GameShell`(장면 배경 + HUD + 하단 도크)을 쓴다.
- HUD 오른쪽 **간단히 보기** 버튼은 장면을 끄고 같은 기능을 목록으로만 보여 준다(선택은 `localStorage`, 접근 불가 시 메모리 폴백).
- 학교 정보(시간표·급식·공지)는 데모 데이터이며 화면에 출처와 확인 시각을 표시한다.

## 입장과 역할

- `/login`에서 **학생**은 이름을 눌러 입장하고, **선생님**은 이름(댓글에 표시)과 교실 PIN으로 입장한다.
- 세션은 서명된 HttpOnly 쿠키(`pen_session`, 30일)다. 학생/교사 화면과 API는 역할별로 막힌다(교사 화면은 학생에게 `/`로 되돌리고, 교사 API는 학생에게 403).
- `TEACHER_PIN`은 개발 환경에서 없으면 `1234`, 운영(production)에서는 반드시 정해야 교사 입장이 열린다. `SESSION_SECRET`이 없으면 `DATABASE_URL`에서 파생한다.
- 댓글 작성자는 항상 로그인한 사람이다(이름 입력칸 없음). 교사 댓글은 "교과 선생님" 배지가 붙는다.

## 교사 화면 (`/teacher`, `/teacher/quests`, `/calendar`)

- **확인함** `/teacher`: 학생이 제출한 퀘스트를 제출 순서대로 보여 준다. 학생 이름·팀, 채운 칸, **인증 사진**, 메모를 보고 **수행 확인 / 다시 시도 / 도움 필요**를 고르고 짧은 피드백을 남긴다. 다시 시도에는 사유가 꼭 필요하다. 최근 확인한 기록은 결정을 바꿀 수 있고, 아래에 오늘 학생 현황(점수·카드별 진행)이 있다.
- **퀘스트 편성** `/teacher/quests`: 학생을 여러 명 골라(전체/팀/개별) **일일 반복** 또는 **주간 목표**를 낸다. 같은 내용도 학생마다 개별 기록으로 저장돼서 나중에 학생별로 멈추거나 지울 수 있다.
  - 일일 반복: 과목·이름·단위(쪽/단어/강의/횟수 체크)·하루 분량·시작 번호, 반복 요일(월~금), 기간(시작~마감), "다음 날 이어서"(쪽·강의), 사진 인증 필수 여부, 학생에게 보일 메모.
  - 주간 목표: 한 주(월~금) 동안 채울 총 분량. 하루 점수에는 넣지 않고, 진행에 비례해 보너스 XP(최대 30)와 코인(최대 6)을 준다.
  - 학생당 요일마다 일일 퀘스트는 최대 3개(약속 3칸). 넘으면 그 학생만 이유와 함께 건너뛴다.
- 오늘 이미 진행한 자기 약속은 덮어쓰지 않는다. 자리가 없으면 다음 수업일부터 나타나고, 편성 화면이 그 학생 이름을 알려 준다.
- 퀘스트를 멈추면 학생이 아직 손대지 않은 오늘/이번 주 카드가 사라지고, 삭제해도 이미 진행한 기록은 남는다.
- 일정 달력은 교사도 같은 화면에서 쓴다.

## 학생의 퀘스트 흐름

1. 선생님 퀘스트는 "오늘 약속" 칸(일일)과 "이번 주 퀘스트"(주간)에 **선생님 퀘스트** 배지로 나타난다.
2. 쪽/단어 칸을 눌러 진행을 기록한다. 사진 인증이 필수면 **사진 찍기**(휴대폰 카메라) 또는 **앨범에서 고르기**로 최대 4장까지 올린다. 사진은 브라우저에서 긴 변 1280px로 줄여 올린다.
3. **선생님께 제출하기**: 칸을 하나 이상 채우고(필수면 사진 포함) 제출하면 "확인 대기"가 된다. 제출 뒤에 칸이나 사진을 고치면 다시 "진행 중"으로 돌아간다.
4. 선생님이 정하면 학생 화면에 상태와 피드백이 나오고, 주간도전 장면의 부엉이가 최신 피드백을 말풍선으로 들려준다.
   - **수행 확인됨**: 카드가 잠긴다.
   - **다시 시도**: 다시 제출할 때까지 그 카드는 점수 0으로 계산한다(잠정). 사진·칸을 고쳐 다시 제출한다.
   - **도움 필요**: 점수는 그대로 인정하고, 선생님이 도와줄 학생으로 표시한다.
5. 선생님 확인이 남은 채 주가 끝나면 순위는 0점 확정이 아니라 **집계 대기**로 표시한다.

## 규칙 (모두 `src/utils/quest-rules.ts`, 테스트 있음)

- 약속 진행률 `f` = 확인한 서로 다른 단위 수 / 계획 단위 수 (0~1, 계획은 1 이상)
- 일간 점수 = `100 × (f1+f2+f3) / 3`, 약속 하나라도 `f = 1`이면 참여 도장 1개
- XP: 약속 칸당 `floor(20 × f)` + 하루 회고 10 → 하루 최대 70. 코인: 칸당 `floor(4 × f)` + 회고 2 → 최대 14
- 레벨 = `1 + floor(누적 XP / 100)`. 코인을 써도 XP·레벨은 줄지 않는다
- 주간 점수 = 대상 수업일(월~금, 오늘까지)의 일간 점수 평균. 지난 미수행일은 0점, 미래 날짜는 미포함
- 대상일 3일 미만은 "기록 모으는 중", 3일 이상은 "잠정", 주가 끝나면 "확정"
- 동점은 공동 순위(1, 1, 3 …). 기본 화면은 상위 3위 묶음 + 내 순위 + 지난주 대비 변화
- 팀 점수 = 팀원 대상일 점수 합 / 팀 전체 대상 학생일 수 (인원이 달라도 평균으로 비교)
- 주간 보상권: 서로 다른 3일(짧은 주는 대상일 수)에 도장을 받으면 1장. 순위와 무관, 모든 경로 합쳐 주 1장
- 배지 우선순위: 폭풍성장(기준선 +20점·도장 3개) › 다시 시작 › 첫걸음 › 꾸준한 도전
- 월요일 00:00(Asia/Seoul)에 주간 점수·순위·도장이 새로 시작하고 XP·레벨·코인·집·진도는 남는다

## 데이터 (Prisma + SQLite)

`Team`, `Student`, `Quest`(교사가 학생에게 내는 반복·주간 규칙), `DailyPromise`(약속 카드: `scope`가 DAY면 하루 칸 0~2, WEEK면 주간 카드, `reviewStatus`·`feedback`·`requireProof` 포함), `PromiseUnit`(쪽/단어 1칸, `promiseId + unitNo` 유일), `QuestProof`(인증 사진 상대 경로), `UploadedFile`(`UPLOAD_STORAGE=db`일 때 사진 본문), `Purchase`(학생·아이템 유일). 기존 `Post`에는 `studentId`를 더했다.

- 같은 칸을 여러 번 눌러도 유일 키 때문에 한 번만 센다(재시도·중복 요청 안전).
- 오늘 약속만 고칠 수 있다(주간 카드는 그 주 안에서). 지난 날의 약속과 교사가 확인한 카드는 잠긴다.
- 업로드는 확장자·브라우저가 준 형식을 믿지 않고 파일 앞부분으로 JPEG/PNG/GIF/WebP만 받는다(SVG 거부, 4MB 제한).
- XP·코인은 저장하지 않고 약속 기록과 게시글(하루 회고)에서 계산한다. 구매만 `Purchase`에 남긴다.

## API

- `POST /api/auth/login` `{ role: "student", studentId }` 또는 `{ role: "teacher", pin, name }`, `POST /api/auth/logout`
- 학생: `POST /api/promise-units` `{ promiseId, unitNo, done }`, `POST /api/proofs`(multipart `promiseId` + `photo`), `POST /api/proof-remove` `{ proofId }`, `POST /api/card-submit` `{ promiseId }` → 모두 카드의 최신 상태(`card`)를 돌려준다
- 학생: `POST /api/shop` `{ itemKey }` → 남은 코인 (`409` 이미 보유/코인 부족)
- 교사: `POST /api/teacher/quests`(학생 여러 명에게 생성), `POST /api/teacher/quest-update` `{ questId, action: pause|resume|delete }`, `POST /api/teacher/review` `{ promiseId, decision, feedback }`
- `GET /api/uploads/[id]` DB에 저장한 사진(불변 캐시, `nosniff`)
- `GET /api/sprites/[name].svg` 서버가 그려 주는 도트 배경·소품·프레임 (불변 캐시)
- 기존 `POST /api/posts`, `/api/comments`, `/api/schedule`은 그대로다.

## 도트 아트 파이프라인

- 글꼴: 갈무리(Galmuri11, OFL) 자체 호스팅 `public/fonts`
- 작은 스프라이트(캐릭터·아이콘)는 ASCII 격자 → 인라인 SVG (`PixelSprite`)
- 건물·나무·소품은 `src/utils/art`의 `PixelCanvas`로 절차 생성 → `/api/sprites`에서 SVG로 제공
- 패널·버튼은 12×12 도트 프레임을 `border-image`로 늘려 모서리가 깨지지 않는다
- 스프라이트 크기표(`manifest.ts`)는 `src/tests/sprites.test.ts`가 생성 결과와 대조한다

## 접근성·움직임

- 상태는 색뿐 아니라 글자·아이콘을 함께 쓴다 (도장, 확정/잠정 태그 등)
- `prefers-reduced-motion`에서는 모든 애니메이션을 사실상 끈다
- 장면 이미지는 모두 `aria-hidden`, 진행 막대는 `role="progressbar"`
